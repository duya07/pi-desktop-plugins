账号池

名称来源密钥状态操作

新增账号

密钥写入插件数据目录的 config.json（明文，权限 600）。宿主给插件进程的是最小环境（PATH/TEMP/HOME 一类），读不到你自己的环境变量，所以这里没有 env 来源。
提示：本 provider 已声明为 authKind: "none"，不需要在宿主「模型设置」里填密钥；密钥只在下方「账号池」添加内联账号。宿主仍会发一个占位 Authorization 头，插件会忽略它。

模型

通道 pin（对后续请求立即生效）

通道列表来自“探测通道”：网关故意 pin 一个不存在的通道，让路由器在花掉 token 前把所有可用通道报出来。校验会把每个通道逐个 pin 一次并记录结论。

模型列表（各模型的参数）

数值来源与参数说明在「导入与参数 → 模型参数」里；这里显示的「官方值」按那个来源算。

导入与模型参数

模型参数决定生成配置的数值，生成后导入宿主即可使用；导入后档位不一致时可一键对齐。

生成配置（导入到模型配置）

生成一份 JSON，拿到宿主「模型配置 → 从其他工具导入」扫描并导入，即可得到可编辑的本地 provider。
生成配置里的模型 id 是 cline-pass-local/<模型>，不是 cline-pass/<模型>。 重命名 provider 没有用，委派 key 仅含 vendorKey 与模型 id。
说明
插件不再自动注册模型，网关需处于运行状态。导入后请在宿主模型卡勾上「可供 AI 自动调度」，子代理才会使用。
为什么要加前缀：宿主给子代理的委派 key 为 <vendorKey>/<模型 id>，自建 provider 的 vendorKey 均为 custom，若模型 id 与直连 api.cline.bot 的那条一致，会撞成同一 key，子代理可能被那条接走（账号池 / pin / 账本均不可见）。
网关两种拼写都认：cline-pass-local/x 与 cline-pass/x 均可路由，旧配置无需手动改回，只是会重新撞名。
  1. 点「生成配置」→ 再点「写入文件」：首次会弹目录选择器，选 C:\Users\<你>\.pi\agent（不存在则先创建）；
  2. 宿主 设置 → 模型配置 →「从其他工具导入」→ 扫描 → 勾选「Cline Pass（本地网关）」→ 导入；
  3. 导入后在该 provider 的模型卡勾上「可供 AI 自动调度」；
  4. 不愿授权写盘可用「复制」手动保存为同一路径，导入后文件可删。
本插件仅向所选目录写入一个 models.json（不读、不删其他文件）。选择器为模态窗口，请在 30 秒内完成；超时后重选即可，目录已记住则秒写。重载后需重选。

导入后档位会回到宿主默认值（off/low/medium/high，默认 medium，选不到 max），可在导入后一键按目录建议对齐。
请在导入之后点。 仅改「base_url 指向本机网关」那一行的 thinkingLevels 与 defaultThinkingLevel，写前已备份，可「撤销」。

模型参数（写进生成的配置）

各模型的参数在「模型与通道 → 模型列表」的卡片里改；改完回到这里点「保存模型参数」批量提交，再回到上方重新生成配置并导入，宿主才会看到新值。
两套均为发布值（非个人偏好），图片能力与显示名始终取自 models.dev。这个下拉与上方「宿主档位」里的是同一个值。
宿主「从其他工具导入」仅认：模型层 id、limit.context、limit.output、reasoning、input、nativeWebSearch。
以下三项需在宿主模型卡手改：思考档位、显示名、是否可供 AI 调度。其余（上下文 / 输出 / 图片 / 有无思考）会按此值生效。
说明
选用哪套决定「官方值」对照、生成配置中的 limit.* 以及网关 /v1/models 广播的数值。例如 deepseek-v4.1-flash 的输出上限 models.dev 为 384000，Cline 目录为 943718；deepseek-v4-pro 档位分别为 high/max 与 high/xhigh。
列表显示为目录 id（cline-pass/<模型>），写入生成配置时会加 cline-pass-local/ 前缀，原因见上方「生成配置」的说明。
「已改」表示该字段被本面板覆盖；「官方值」仅作对照，不会自动回写。档位控件来自 models.dev：有 effort 为滑杆、toggle 为开关、none 表示无思考档位。
宿主显示规则：limit.context / limit.output 会在导入后落为 contextWindowSource / maxTokensSource = "user"，即显示此处填写的值；若为 "catalog" 则显示宿主从 models.dev 查得的值，查不到为 -- · --。本 provider 地址 127.0.0.1:41593/v1 与 models.dev 中本机 provider （:1337 / :1234 / :8081）对比为协议+host:port 全等，因此永远查不到，需显式提供数值。
请勿在宿主中向此 provider 手动添加其他模型 id（如 deepseek/deepseek-v4.1-flash），仅会显示 -- · --；如需该模型的官方元数据，请加到直连 api.cline.bot 的 provider（models.dev 中有 cline-pass 对应项）。
逐个提交「模型与通道 → 模型列表」里改过的字段；没有改动的模型不发请求。

官方额度

数字来自 Cline 官方接口 GET /users/me/plan/usage-limits，显示的是该账号的已用比例（条长=已用，≥90% 红、≥70% 橙）； 和下面「用量」那张卡的本地账本不是一个口径 —— 账本只统计经过本网关的请求，官方额度里还包含这个账号在别处用掉的量。 只列插件读得到密钥的账号（「账号池」里那几条内联账号）；本 provider 为 authKind: "none"，宿主的占位 Authorization 头会被忽略，不在此列。

网关设置

怎么用

1. 本 provider 已是 authKind: "none"，无需在宿主「设置 → 模型 / Providers」里填密钥；密钥只在插件面板「账号池」里添加内联账号（宿主仍会发一个占位 Authorization 头，插件会忽略）。
2. 先到「模型与通道」点「生成配置」生成 JSON，拿到 PI-Desktop 的 模型配置 →「从其他工具导入」导入，得到你自己的 provider 后再在模型选择器里选导入后的模型；请求会经本机网关转发到上游，pin / failover / 账号轮询都在网关里生效。
3. 网关只监听 127.0.0.1；插件卸载或禁用时端口会被释放。
